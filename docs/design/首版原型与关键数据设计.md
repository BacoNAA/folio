# 首版原型与关键数据设计

2026-11-04 更新。随手记、草稿和找回入口的使用流程已确认。具体控件和数据关系以本页样稿和草案继续评审。[首版范围、主流程与迭代安排](../requirements/版本规划与审核事项.md)

## 查看与操作

用浏览器打开 [prototype.html](prototype.html)，同目录的 CSS、JavaScript 文件需保留在一起，无需安装依赖。也可在仓库根目录运行 `python -m http.server 8765 --bind 127.0.0.1 --directory docs/design`，访问 `http://127.0.0.1:8765/prototype.html`。

原型使用虚构数据，仅在页面内存中保留编辑结果；刷新或“重置示例”恢复初始状态。照片使用图形示意，录音与定位使用明确标记的模拟操作，不访问设备、不上传内容。原型展示的是首版主要流程，不是安卓应用或数据持久化实现。

可以用同一次探店体验走通三条路径。

1. 打开「随手记」，先拍一张示意照片，再补一句「微辣刚好」。离开编辑，到「记录」点「继续草稿」续写。完成后回到「随手记」，通过「已保存 · 查看」打开原记录。
2. 留下两份不同的新建草稿。进入「记录」查看草稿列表，凭文字、照片或录音时长找到想续写的那份。只完成其中一份，再到「搜索全部记录」查找。
3. 从「记录 → 按地点」按名称、城市或地址找到地点，进入小册搜关键词。去掉地点条件后继续用同一关键词找其他地点的记录。从小册直接打开一条已有记录并修改，完成后先看详情，再返回小册。

## 本轮五项设计评审

| 待评审设计 | 样稿中的具体方案 | 评审重点 |
|---|---|---|
| 视觉与导航 | 一级入口为「随手记」和「记录」。打开先到「随手记」，点「写一句」才开始文字输入，拍照、选图、录音和清单可直接开始。暖白和墨绿是样稿配色 | 各种内容是否同样容易开始，控件是否易辨认 |
| 记录与草稿 | 「记录」默认按时间浏览，可切换「按地点」。有一份草稿时直接续写，多份时按最近编辑排序，用文字片段、照片缩略图或录音时长辨认 | 从正式记录和草稿中能否找到想接着写的内容 |
| 连续编辑 | 可在同一条里继续添加不同内容。新建完成回到「随手记」，可点「查看」。修改已有记录完成后回到详情，再返回原浏览来源 | 能否继续记录下一件事，或接着看刚才浏览的内容 |
| 时间与查找 | 记录页搜索全部正式记录，地点列表查地点资料，小册内按当前地点查正式记录。搜索时可移除可见的地点条件并保留关键词 | 能否看出正在查哪一类内容，以及怎样扩大范围。月份、季节、范围和重叠时间的完整布局待细化 |
| 地点与恢复 | 「记录 → 按地点 → 地点小册」打开关联记录。编辑时可复用或新建地点，坐标由用户选填。回收站可以逐条恢复或彻底删除 | 地点和原记录的关系、删除与恢复反馈是否清楚 |

本表评审具体呈现和控件，已确认的功能规则沿用正文。样稿中的 6 秒撤销提示只是演示参数，正式时长尚待设计。下一步根据评审意见调整同一套原型。

## 数据关系草案

以下是安卓实现的逻辑设计，尚未建立数据库或冻结表结构。沿用已确认的 Room／SQLite 与应用持久文件目录方案。

| 数据 | 身份与主要内容 | 关系与约束 |
|---|---|---|
| 记录 | 稳定 recordId、首次记录时间、修改时间、删除状态 | 页面、搜索和地点小册始终引用此身份；首次记录时间不随补写改变 |
| 正式内容与草稿 | 草稿有独立身份、最近编辑时间及续写位置，保存内容集合、事件时间、标签及对象关系。已有记录的编辑草稿另带起始正式版本标识 | 用户可同时保留多份新建草稿，并逐份续写或完成。已有记录同时保留正式内容与未完成修改。内部版本标识用于防止旧草稿覆盖新改动 |
| 内容项 | 稳定 itemId、所属内容集合、排列顺序、文字／照片／声音／清单类型 | 同类可重复追加。照片、声音项引用媒体；清单保存事项与勾选状态；数据顺序不意味着本轮增加拖拽排序功能 |
| 媒体 | 稳定 assetId、本地相对路径、类型、保存状态及必要元数据 | 原始文件保存在持久目录；缩略图可重建。正式内容、草稿和回收站中仍被引用的原文件均保留 |
| 事件时间 | 精度、用户原说法、已明确的起止范围；精确时间的必要时区信息 | 未知不填伪日期；年份、月份、季节与范围保留自身精度。季节保存当时采用的范围，后续规则变化不改旧记录 |
| 地点／人物／物件 | 稳定 objectId、对象类型、名称及已支持的区别信息 | 同名不合并；记录通过关系引用对象。地点增加可选城市、地址和坐标，补正位置不改变 objectId；字段随其能力上线 |
| 标签与记录关系 | 稳定 tagId、显示名称；记录内容集合到 tagId／objectId 的引用 | 修改草稿中的归属不改变正式归属；同一标签更名显示同步。星标／置顶作为记录上的标记，不复制记录 |

地点小册与搜索是读取这些数据的视图，不另存记录正文。人物与物件小册、图谱、章节等仍按原有批次安排，不为原型新增产品需求。

## 保存、完成与恢复

1. **编辑时**，新建内容使用自己的草稿，修改已有记录使用与原记录关联的草稿。主动离开后可以另记一条。临时切换应用再返回时继续当前编辑。新建对象的待保存信息暂随草稿保留，只有完成后才进入正式的地点等入口。
2. **媒体进入草稿时**：先将原始文件完整写入应用持久目录并确认可读取，再写入草稿引用；任何步骤失败都如实提示，保留此前成功内容。数据库与文件系统无法共用一个数据库事务，设计上通过写入顺序和可重试状态衔接；中断后检查未关联文件，不能先删仍有引用的媒体。
3. **点击完成时**，校验实际内容及媒体状态，在一个数据库事务中更新正式内容、关联和修改时间，完成待保存对象的建立，并移除本次提交的草稿。事务失败时保留原正式内容和草稿。提交成功后，新建记录回到「随手记」并提供查看入口，旧记录回到详情，各浏览入口随提交结果刷新。
4. **放弃修改时**：移除草稿，保留原正式内容；仅清理已无正式、草稿或回收站引用的媒体。若草稿建立后相关信息被其他入口修改，先检查版本与关系，不静默覆盖；具体冲突提示随设计细化。
5. **删除与恢复时**：记录进入回收站，暂不出现在普通浏览与搜索；正式内容、关联及已有草稿随之保留。恢复时找回仍有效关系，目标已不存在则不重建。彻底删除前确认，之后移除该记录与草稿的引用，再清理无其他引用的媒体；不自动按天清理。

对象恢复及媒体保留遵循[删除恢复共同规则](../requirements/H-隐私与数据保护.md#删除恢复的共同规则)。删除时已有未完成草稿的具体交互为本草案建议，需要在原型评审中结合实际操作核对。

## 浏览与查询的边界

- 普通记录搜索读取有效正式内容。草稿从「继续草稿」进入，删除的内容从回收站进入。地点列表以名称、城市、地址查地点资料。小册搜索按地点身份限定正式记录，去掉地点条件保留关键词。文字匹配覆盖当前已支持的正文、说明和线索。安卓上的中文查询方式仍待验证。
- 模糊时间按已知范围匹配，范围可能相交的结果保留“可能”的含义，不把未知日期猜入某年。无法确定精确先后时按范围呈现，不用记录时间冒充事件顺序。
- 坐标保存数值、坐标类型与来源，不能混用不同来源而不标识。首版主动定位成功后由用户确认；地图接入仍后置。
- 原型仅演示日期、年份、自由描述及未填写；年份筛选选项为示例值。月份、季节和范围的输入，默认季节月份与跨年归属仍待细化，原型不暗定这些规则。
- 样稿中人物和物件各用一个文本框演示线索区域，尚未实现多对象选择及完整身份模型；地点演示稳定身份、新建与复用。按具体对象组合过滤、地点更名及已有地点的位置补正等界面待下一轮细化，均仍属于已确认范围。

## 验证记录

2026-11-04 通过 Chrome 核对以下路径。

- 启动时显示「随手记」，点「写一句」才聚焦输入框。空编辑退出或取消模拟选图后，草稿数保持原值。
- 模拟拍照后退出并续写，单条草稿直接打开。多份草稿可分别打开，最近编辑的排在前面。文字摘要、照片缩略图、声音时长和清单摘要可用。完成其中一条回到「随手记」，点「查看」打开该条，另一份仍可续写。
- 从按时间浏览、搜索结果和地点小册修改已有记录，完成后回到该条详情，再返回原浏览入口。搜索词保留。
- 在地点列表用名称、城市和地址查找。在小册内按一个关键词找到一条记录，清除地点条件后，同一关键词找到两条。普通结果排除草稿和回收站记录，恢复后可再次找回。
- 检查了 320、390 和 1280 像素宽度下的主要入口，并在 390 × 844 视口保存新版[手机预览图](prototype-mobile.png)。本轮操作中浏览器控制台没有报错。

此前已走查文字、照片示意、录音示意与清单的混合提交，以及文字、媒体类型、星标的组合筛选。浏览器验证覆盖样稿中的状态和导航。安卓软键盘、系统回收进程后的恢复、持久保存、设备媒体、定位、权限与覆盖安装仍由相应 APK 验证。
