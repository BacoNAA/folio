# 第二版专题 · 浏览与回看

[返回第二版需求草案](../第二版需求草案.md)

用户可能只记得一个同行人、一个季节，或者阳台刚搬来时的样子。入口要适应用户手上已有的线索。第二版拟优先细化对象小册中的照片对照、连续观察，以及按事件日期或季节回看。星图可独立交付。文中的页面入口、分批选择和异常处置建议供评审。时间、引用与私密的既有规则分别以[时间章节与回看](../D-时间章节与回看.md)、[整理关联与查找](../B-整理关联与查找.md)及[隐私与数据保护](../H-隐私与数据保护.md)为准。

## 先从现有入口出发

| 用户记得什么 | 建议路径 | 用户离开详情再返回时 |
|---|---|---|
| 记得时间或同行人 | 记录 → 搜索全部记录 → 选择时间、人物和媒体条件。若启用引导式找回（R026），逐步询问这些线索，允许跳过不确定项。 | 保留词、已选对象、结果分组和可用的滚动位置。用户主动移除条件才扩大范围。 |
| 记得地点或物件 | 进入地点或对象小册，查看正式记录。从照片选取「对照」或「加入观察」，查看资料后仍能回到当前对象。 | 保留对象身份，同名地点、同名物件各自有独立结果。对象改名后继续指向原对象。 |
| 想知道往年这个时候做了什么 | 建议从「记录」进入回看，自主打开历年同日、季节回信。输入入口仍可直接记录一句话。 | 从回看打开的是同一条正式记录。返回原先的日期或季节。无符合内容时可正常离开。 |
| 只记得大概在哪片地方 | 建议在「按地点」中切换列表与星图。点选星点打开已有地点小册，列表保留无坐标地点。 | 返回之前浏览的区域或选中的地点。只有一个地点时也能查看。 |

准确的日期、范围与来源由本机后端统一解释。页面负责收集条件、说明匹配原因、保存浏览位置。首版已有[事件时间模型](../../../app/src/main/java/com/baconaa/folio/records/RecordTime.kt)和[正式记录查询](../../../app/src/main/java/com/baconaa/folio/records/RecordQuery.kt)，新入口应能使用相同的业务规则。下列结果是待实现能力的接口约定建议。

## 同日与季节怎样选取记录

| 输入与状态 | 可观察结果 |
|---|---|
| 一条事发生在东京当地 2024-11-08 的正式记录，2025 年才在另一时区补记 | 选择 11 月 8 日能回看这条记录。补写日期仍可从记录时间浏览。仅知「2024 年秋天」的另一条记录参与季节回看。 |
| 默认冬季，原记录写「2025 年冬天」，保存范围为 2025-12-01 至 2026-02-28 | 查看该冬季能显示原来的说法。按 2026 年筛选时为部分相交。以后调整季节设置再打开这条记录，其已保存的日期范围不变。 |
| 只有「大学时」，没附范围。另一条是「大学时（2018—2022 年）」 | 前者在时间未定或其他已知条件下可找到。后者按已存范围判定明确或可能。两种内容均可由用户手动收入章节。 |
| 在季节回看中明确排除某条记录，或启用了单条私密 | 按用户选择排除。已启用的私密记录默认不在同日、季节及随机回看中主动呈现，完整备份的收录规则另见[升级备份与恢复](升级备份与恢复.md)。 |

历年同日（R043）按明确月日查找。建议 2 月 29 日只匹配确有该月日的旧记录，无匹配时不展示同日内容。季节回信（R045）沿用保存的时间范围。部分相交的结果可查看“为什么可能符合”。建议只在用户主动打开时显示季节回看，通知策略另议。一次加载失败应提供重试。成功查得零条才显示相应空状态。

## 两张照片与多次观察

**照片对照（R041）**　建议从小册或记录详情选择第一张照片，进入第二张照片的选择页。确认前可返回、更换一张或取消。并排查看时，两侧各自显示来源、事件时间原文和照片说明，各自能打开所属记录。无法定先后时直接保留用户的左右选择。首批建议先支持一次查看。把对照组合长期收藏属于另一次范围选择。

**变化轨道（R047）**　用户先明确观察对象，再挑选正式记录中的代表素材，可加一句自己的说明。例如选择「刚搬来」和「第一次开花」两次观察，之后再补「重新布置」。首次只有一个节点也可保存。建议每个节点引用稳定的记录与素材标识，并单独保存观察说明。用户编辑说明或移出节点时，原记录仍可从原处打开。事件日期按原始精度显示，时间有重叠或未知时保留这种不确定性。

**原素材发生变化**　建议在选取完成时复核素材仍可读。源记录进回收站后，其内容沿用回收站可见性。已经打开的对照给出哪一侧暂不可用，并保留另一侧和返回入口。恢复同一条记录及素材后可再次查看。若用户在正式编辑中永久移除了选定照片，可重新选择来源，应用应避免用同记录中的下一张照片顶替。变化轨道的节点排序平局、隐藏节点是否显示占位及是否允许长期保存对照组合，随页面设计复核。

## 地点星图与真实地图

地点星图（R037）使用已保存的地点身份和可用坐标。建议输入为当前地点集合与已选地点，输出包含地点标识、名称、可选代表照片及展示位置。用户点星点选中地点，点名称进入同一本小册。同坐标或过近的点提供可选择的地点列表，用城市、地址或备注区分。取消定位权限后仍能使用已有坐标。无坐标时仍能在列表进入小册，新建记录也可仅填地点名称。

最小批次以手工可复验的三个地点为样本，一处有坐标、一处名字相同但坐标不同、一处没有坐标。核对星图打开正确的小册、无坐标地点在列表可找。再在小册更正其中一处坐标，重新打开星图时使用新位置。组内主题筛选与经历连线可随成组后增加。只有用户确认的顺序可用于连线。到访次数需要明确的到访事实。

真实底图（R036）单独选期。建议先比较目标地区覆盖、可用授权、离线区域下载和过期后的体验，再决定是否采用某个 SDK。选定后，验收要能从下载完成、断网、冷启动一路走到打开地点原记录。未下载区域提供地点列表。现阶段沿用[地点与空间](../C-地点与空间.md)的选型边界。

## 前后端交接与验收

| 操作 | 前端提供 | 本机后端返回或保证 |
|---|---|---|
| 查询回看 | 模式、查看的日期或季节、已选范围、排除项。私密可见性沿用应用约定 | 当前可见的正式记录标识、匹配类别、日期原文及实际范围。明确区分读取失败与成功的空结果。 |
| 查看素材或保存观察 | 对象、记录、素材的标识和用户说明。每次确认的操作只提交一次 | 可读取的来源，或可区分的失效原因。存储完成后返回可再次读取的观察结果。多次进入页面不会新增节点。 |
| 打开星图小册 | 所选地点标识。范围和位置留在页面状态 | 对应地点资料与正式记录。显示名称可重名。无可用坐标时仍返回已知地点资料。 |

## 任务卡

V01–V04 为本专题建议优先细化的能力，V05–V10 为待选扩展。日期判断适合用查询样本验证。涉及返回位置、选错原片或地点身份的行为，从模拟器上的对应入口复验。

### V01 历年同日与季节回看

- **需求依据**　R043、R045 及 R012 的[时间匹配规则](../D-时间章节与回看.md#时间浏览与匹配共同规则)。
- **本次范围**　从「记录」主动打开同日或季节回看，展示日期、时间精度、可能命中的理由，并能打开原记录。保留用户对季节回看的排除选择。
- **接口与依赖**　前端传模式、参照日期或季节，后端按当地事件日期、已存范围与可见性返回记录及匹配说明。首版时间模型已可复用，启用私密记录后接入统一过滤。
- **验收例子**　准备去年 11 月 8 日的记录、只有「去年秋天」的记录和仅有「大学时」的记录。11 月 8 日回看只命中第一条。秋季回看可找到前两条。排除第二条后重开仍保留选择，全局查找能打开原记录。

### V02 两个时间点的照片对照

- **需求依据**　[R041 那时与现在](../D-时间章节与回看.md#r041-那时与现在)。
- **本次范围**　手选两张已有照片，并排展示、换片、查看日期与说明、返回各自原记录。首次从已有详情进入，对象小册上线后可复用同一入口。
- **接口与依赖**　前端保存左右侧选择和浏览来源，后端以正式记录 ID 与照片项 ID 读取对应原件和日期。复用现有照片详情与回收站规则。
- **验收例子**　一条入住记录里有客厅、阳台两张照片。选其中的阳台照片与今年重拍的阳台对照，两侧分别打开正确来源。把一侧源记录移入回收站再返回，另一侧仍可查看，失效侧可重新选片。

### V03 为对象保存变化轨道

- **需求依据**　[R047 变化轨道](../D-时间章节与回看.md#r047-变化轨道)。
- **本次范围**　选定对象，手动加入正式记录中的观察节点，填写说明，继续追加或移出节点。单个节点即可保存，日期保留原始精度。
- **接口与依赖**　前端传对象、来源内容项和用户说明，后端保存节点身份及来源关系并读回。复用首版对象身份。持久化节点与说明纳入完整备份。无法判断先后的节点如何显示按专题建议评审。
- **验收例子**　给同一盆花添加「买回来」与「开花」两个节点，其中一条只知月份。重启后仍能打开两条来源，月份没有被补成某一天。移出一个节点后原照片仍在记录详情。

### V04 地点星图与小册跳转

- **需求依据**　[R037 地点星图](../C-地点与空间.md#r037-地点星图)。
- **本次范围**　在列表与星图间切换，点选有坐标的地点进入原小册。无坐标地点留在列表。主题连线可后续选入。
- **接口与依赖**　前端传回所选地点 ID 并保留浏览区域。本机后端提供已存坐标、名称和区别信息。依赖首版地点资料，星图可离线工作。
- **验收例子**　准备两个同名不同地址的咖啡馆及一个无坐标地点。关闭定位权限后点任一星点，按地址核对小册；从列表仍能打开第三处。修改已选咖啡馆的坐标，返回星图可见新位置。

### V05 按线索逐步找回

- **需求依据**　[R026 引导式找回](../B-整理关联与查找.md#r026-引导式找回)及首版组合查找规则。
- **本次范围**　从搜索入口依次选择记得的年份、地点、人物或内容类型，可跳过、回到上一步或单独放宽条件。展示当前查找范围。
- **接口与依赖**　前端将每一步的选择转为现有筛选条件，后端返回有效正式记录及匹配类别。复用规则查询，可独立于自然语言找回开发。
- **验收例子**　指定小林与照片后再加年份得到零条。移除年份找回旧照片，打开详情再返回人物与照片条件仍在。跳过地点这一步不会填写任何默认地点。

### V06 逐级浏览时间与章节

- **需求依据**　[R046 时间缩放](../D-时间章节与回看.md#r046-时间缩放)。
- **本次范围**　从年展开到月、日再返回，保留层级和位置。支持章节时，可从并列的章节进入其手选成员。
- **接口与依赖**　前端提供时间层级或章节 ID，后端按已知精度返回分组；章节视角依赖基础章节。普通日历视角可独立交付。
- **验收例子**　准备一条日期明确的记录与一条仅知年份的记录。进入具体某日能看到精确匹配，返回年份能找到大概时间分组。G03 上线后，把第一条记录收入两个章节，切换章节核对两个入口是否打开同一来源。

### V07 在选定范围内随机回看

- **需求依据**　[R053 随机翻牌](../D-时间章节与回看.md#r053-随机翻牌)。
- **本次范围**　选择全部记录或已开放的组、章节，查看一条符合条件的正式记录。允许排除不想出现的内容，空范围可改选。
- **接口与依赖**　前端传范围与排除动作，后端先处理可见性、回收站与排除项，再返回可打开的记录或空结果。组与章节仅在各自上线后加入选项。
- **验收例子**　在仅有三条记录的测试安装中，把一条移入回收站、一条设为排除，从全库翻牌只能打开第三条。将第三条也排除后应显示空结果。G01 或 G03 上线后，再选一个组或章节作为范围，核对翻出的记录属于该范围，返回后仍保留选择。

### V08 从照片主色找回原记录

- **需求依据**　[R052 照片主色浏览](../D-时间章节与回看.md#r052-照片主色浏览)。
- **本次范围**　在本机按色系浏览照片，看到命中的具体照片，打开原记录。评审时用代表照片确定首批颜色分组。
- **接口与依赖**　后端按照片项返回主色与所属记录。前端维护所选色系和列表位置。复用已有本机原件及有效正式内容查询。
- **验收例子**　一条记录同时放蓝色海面与橙色灯光。切换色系时各显示对应照片，点开均回到正确原记录。删除其中一张并完成后，保留的照片仍可按颜色找到。

### V09 设定未来日期再回看

- **需求依据**　[R044 未来胶囊](../D-时间章节与回看.md#r044-未来胶囊)。
- **本次范围**　手选记录、设定开启日期、在应用内到期查看。允许提前查看并保存相应状态。系统通知方式另行决定。
- **接口与依赖**　前端展示所选内容、日期与当前状态。后端保存稳定引用、开启日期与查看状态，纳入恢复范围。
- **验收例子**　用两条正式记录各设一枚未来胶囊。提前打开第一枚，重启后仍显示提前查看。对第二枚切换到约定日期后，在应用内可看到到期入口并打开其原记录。

### V10 真实地图与离线区域

- **需求依据**　[R036 地图底图](../C-地点与空间.md#r036-地图底图)和[版本规划](../版本规划与审核事项.md)中的地图调研。
- **本次范围**　候选卡。先核实目标地区、许可和离线支持。选型通过后，用户可主动下载一个受支持区域，在断网时从地图进入地点小册。
- **接口与依赖**　界面展示区域、下载状态和时间，按地点 ID 跳转。本机地点资料与底图数据分开保存。依赖实际选定的地图服务和可验证的区域样本。
- **验收例子**　下载一个受支持的城市区域后断网并冷启动，点一个已存地点打开正确小册。切换到未下载区域时仍可从列表找回记录。若授权不支持离线，记入选型结论，此项继续待选。
