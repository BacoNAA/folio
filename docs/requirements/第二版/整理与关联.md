# 第二版专题 · 整理与关联

[第二版需求草案](../第二版需求草案.md)

小林把购买咖啡机、第一次试用和送修各写成一条记录。点咖啡机能看它的经历。点维修记录能直接找到当时的凭证。在「新家入住」资料组里还可以按自己的顺序读这些材料。这三个入口共用原记录，各自回答「关于谁或什么」「这两条有什么联系」「我想一起看哪些内容」。

第二版拟优先细化基础成组、导览、轻量章节、人物与物件小册及记录直接关联。下文沿用现行正文中的产品规则。具体入口、按钮名称、保存手势和待选方案均为本轮建议。个性化标记和地点体验可分别选入。[整理、关联与查找](../B-整理关联与查找.md) · [版本规划](../版本规划与审核事项.md)

## 正式记录与整理资料的边界

| 用户正在改什么 | 何时生效 | 其他入口能看到什么 |
|---|---|---|
| 原记录的内容及本条归属的人物、物件、地点 | 沿用草稿与「完成」。草稿中新建的对象随该记录完成后成为共享对象 | 完成前从组、章节、小册或直接关联打开，均看到上次完成的内容。新建草稿留在「继续草稿」 |
| 人物或物件的名称、别名、区别说明 | 在共享对象资料中保存。建议从小册进入既有编辑能力 | 引用同一对象的记录、选择面板和搜索采用当前资料。此前打开的记录草稿继续指向同一对象 |
| 组或章节的收录、移出、顺序，组内的导览文字 | 建议由对应整理页面独立保存。组内卡片读取正式记录的当前内容 | 调整资料的阅读顺序只作用于当前组。记录自身的事件时间、记录时间、正文及其他组的顺序保持原值 |
| 两条正式记录之间的直接关联 | 建议从记录详情建立、更换或解除，动作成功后两端同步 | 编辑中改正文、放弃正文草稿或调整组内成员，均保留已经独立保存的有效关联 |

对象、记录和记录组使用各自稳定的身份。名称、别名、卡片显示标题或数组位置仅用于展示。用户可随时只留一句话并保存。全局搜索仍找得到未作任何整理的正式记录。[已确认的保存关系](../../design/首版原型与关键数据设计.md#已确认的保存关系)

## 任务卡

G01 从首版正式记录、草稿与回收站开始，可与媒体导入并行。G02 与 G03 分别复用 G01 的收录能力。G04 与 G05 可以直接使用首版对象与正式记录身份。G06 至 G10 是候选增强，随对应能力选入。下列按钮与写入时机按本轮建议描述，例子供后续开发验收。

### G01 基础成组与成员恢复

**领取状态**　`codex/record-groups` 已完成本机后端与安卓页面接入，调试包已走通下方多选成组、组内调序和回收站恢复样本。[本机接口](../../../app/src/main/java/com/baconaa/folio/records/RecordGroups.kt) · [接口与验证进度](../../engineering/开发流程.md#第二版-g01-基础成组与成员恢复)

**需求依据**　[R102 记录成组](../B-整理关联与查找.md#r102-记录成组)、[R018 单份引用](../B-整理关联与查找.md#r018-引用而不是复制)、[R027、R028 删除与恢复](../H-隐私与数据保护.md#h1-删除与恢复)。

**本次范围**　从「记录」多选已完成的内容，新建命名组或加入已有组。无标题记录沿用现有摘要。组内可按选择顺序追加、用按钮调整顺序、移出成员、打开详情再返回。删除组只解除其中的收录。组内仍可使用原记录的删除、撤销与回收站恢复入口。

**接口与依赖**　使用首版的[正式记录 ID、摘要和详情接口](../../../app/src/main/java/com/baconaa/folio/records/TextRecords.kt)。前端保留选择、顺序和返回位置。本机后端独立保存整理动作，按组 ID 读回组名及可见成员的有序摘要。空组可继续添加记录，组已删除时可返回组列表，读取失败时可原地重试。

| 操作 | 前端提交 | 本机后端的结果 |
|---|---|---|
| 新建并收录 | 本次新建使用的稳定标识、非空组名、按选择顺序排列的一条或多条正式记录 ID。首次确认与结果未知时的重试共用该标识。 | 在同一事务中保存组及首批成员，返回稳定组 ID 和实际成员顺序。若首次已成功，重试读回原组。 |
| 加入已有组 | 目标组 ID、按选择顺序排列的正式记录 ID。 | 仅将尚未收录的成员依次追加到末尾。新建和追加都先校验本次选择，若有记录已进回收站，本次整体不写入，返回失效的记录 ID，页面保留有效选择供再次确认。 |
| 调序、移出或删除组 | 调序提交组 ID、打开时的成员顺序与调整后的顺序。移出提交组 ID 和成员 ID。删除组提交组 ID。 | 调序前核对当前可见顺序，若已变化，返回最新顺序供用户再调。移出仅解除指定收录，最后一个成员移出后仍可打开空组。删除组后，原记录及其他组内的收录仍可用。 |

撤销删除或从回收站恢复时，每个仍存在的组按自己的顺序恢复收录。组内未发生变化时回到原位。顺序有变化时，在当前可见成员中找到删除前紧邻的前一项，插在它之后。若原前项不在，再插到仍在组内的原后项之前。两者均不在时追加到末尾。保留其他成员的相对顺序，已删除的组保持删除。[Q17 恢复规则](../待确认问题.md)

**验收例子**

1. 按「购买、试用、维修」顺序选三条正式记录，新建「购机资料」。后端用同一次创建标识重试一次，模拟首次已写入但结果未送达。重开只有一个新组，返回同一组 ID，成员各一条且顺序如初。将「试用」再收入「家庭收藏」，向两组重复追加它，每组仍各有一条。打开组员详情再返回，用按钮调序并从首组移出「维修」，全局搜索仍能打开维修记录。
2. 重新收录「维修」，将「购机资料」排为「购买、试用、维修」。为「试用」留下未完成的修改，再把它移入回收站。组内和搜索均隐藏该记录。立即撤销后从原组原位置打开上次正式内容，并能继续未完成的草稿。
3. 再建「原件」「售后」两组，均按「购买、试用、维修」收录。将「试用」移入回收站后删除「家庭收藏」，将其余三个组分别调整为下表中间列的顺序。恢复一次，「家庭收藏」保持删除，其余各组独立得到右列的结果。三行可共用同一次后端验收。

| 所在组 | 恢复前可见顺序 | 恢复后的顺序 |
|---|---|---|
| 购机资料，原前项和原后项均在，次序已反转 | 维修、购买 | 维修、购买、试用 |
| 原件，原前项已移出 | 维修 | 试用、维修 |
| 售后，原前项和原后项均已移出，新收录一条「保修单」 | 保修单 | 保修单、试用 |

### G02 专题导览

**领取状态**　`codex/group-guides` 已完成本机接口与页面接入，下方「购买、送修」样本已在 API 36 模拟器验证。[接口与验证进度](../../engineering/开发流程.md#第二版-g02-专题导览)

**需求依据**　[R103 可选专题页](../B-整理关联与查找.md#r103-可选专题页)、[R102 记录成组](../B-整理关联与查找.md#r102-记录成组)。

**本次范围**　从普通组增加整组说明、分段标题、说明与阅读顺序。在段内打开成员后可返回原段。建议删除分段前提示受影响条数，其成员仍可在组内未分段区阅读。只有一条成员或没有导览说明的组均可继续使用。

**接口与依赖**　依赖 G01 的组 ID、有序成员和详情入口。前端发送段的身份、成员身份、编辑前后次序及说明。后端将段落安排与顺序一起保存，只保留一份收录。保存失败时保留编辑缓冲。成员在别处被移出或重排时，返回当前顺序供重新安排。

**验收例子**　把「购买凭证、维修单」收进同组，分别编入「购买」「送修」两段。把「送修」移到「购买」之前，保存并重开。从第一段进入维修详情再返回，应回到「送修」。删除「送修」时应提示有一条成员会移至未分段区，确认后仍能从组中打开维修单。再编辑导览时，从另一入口把维修单移出整组，回到旧编辑页保存，界面应指出该成员已移出，原有选择不会把它重新收录。

### G03 生活章节

**需求依据**　[R042 轻量生活章节](../D-时间章节与回看.md#r042-轻量生活章节)、[R012 模糊时间](../D-时间章节与回看.md#r012-模糊时间)。

**本次范围**　从「记录」创建命名章节，可填时间背景、一句说明和封面，手动收录、移出或排序。允许不完整日期、重叠章节及只有少量记录的章节。建议只有起点或只知年份时按原精度展示。更改章节时期后，已有成员和各条记录的事件时间由用户分别维护。

**接口与依赖**　复用 G01 的收录与顺序，无需先完成导览。前端提供章节身份、用户填写的起止时间与精度、说明、封面来源及选中记录。后端保存章节资料与原记录引用，对明确颠倒的起止日期返回可修正的问题。封面来源失效时可换图，已有章节仍可读。

**验收例子**　建立「第一次独居」与「杭州实习」两个日期重叠的章节，将一条搬家记录放入两章，再收录一条仅写「大学时」的记录。缩短第一章的时期，再把搬家记录从第一章移出。第二章及全局搜索仍可打开它，「大学时」仍按原话显示。尝试保存早于起点的明确终点，在编辑页修正后可继续保存，原有收录保持完整。

### G04 人物与物件小册

**需求依据**　[R015 人物与物件线索](../B-整理关联与查找.md#r015-人物与物件线索)、[R016 同名对象](../B-整理关联与查找.md#r016-同名不自动合并)。

**本次范围**　从人物物件列表或记录详情中的对象打开独立小册。支持按名或别名查找、区分同名对象、在小册内找正式记录、改共享资料、从详情返回原位置。零条记录的对象仍可查看资料及在新记录中选用。

**接口与依赖**　沿用首版的[对象读写接口](../../../app/src/main/java/com/baconaa/folio/records/RecordObjects.kt)和正式查询。前端给出对象 ID、筛选词与来源位置。后端返回对象资料和属于该 ID 的正式记录。改别名按对象保存。更改一条记录的对象归属则在其草稿点「完成」后更新小册。读取失败与成功读到零条分别返回，失败可在原范围重试。

**验收例子**　建两台同叫「咖啡机」的物件，用「家用」「办公室」区分，给家用机器添加别名「小白」。按别名进入家用小册，只能找到家用记录。编辑一条维修记录将归属改至办公室，暂离时仍在家用小册。续写并完成后归属切换。移走最后一条记录后，家用机器仍可按原别名找到并选用。

### G05 双向记录关联与纠错

**需求依据**　[R017 手动关联记录](../B-整理关联与查找.md#r017-手动关联记录)、[R019 关联纠错](../B-整理关联与查找.md#r019-关联纠错)、[删除恢复规则](../H-隐私与数据保护.md#删除恢复的共同规则)。

**本次范围**　从正式记录详情选取另一条正式记录，建立联系、双向查看、更换错误目标或解除联系。候选列表排除当前记录，已有关系带「已关联」提示。已入回收站的记录从正常选择和跳转中隐藏。共用对象或同组本身不会创建直接关系。

**接口与依赖**　依赖首版正式记录身份与回收站。前端提交来源 ID、原目标与新目标。后端一次完成更换，保证两端读到一致的关系，重复建立同一对关系可读回原结果。若新目标刚被删除，保留旧关联并让用户重选。建议当两端均已从回收站恢复时重新显示其有效关系，彻底删除任一端后解除相应引用。

**验收例子**　在「维修单」关联「旧凭证」，再换到「新凭证」。分别打开三条记录，旧凭证不再有该关联，新凭证可返回维修单。将一个候选目标放入回收站后再提交更换，旧关系仍可双向打开。解除当前关系后续写一份此前建好的正文草稿，完成编辑后双方仍无此关联，两条记录可独立查找。

### G06 个人图章

**需求依据**　[R097 个人图章标签](../B-整理关联与查找.md#r097-个人图章标签)、[R021 自定义标签](../B-整理关联与查找.md#r021-自定义标签)。

**本次范围**　候选。从标签入口选图标、照片局部或导入小画，命名图章，给记录添加并按名称找回。已有正式标签可独立更名或换图。草稿中新建图章沿用新标签的发布时机。

**接口与依赖**　复用基础标签身份、草稿完成和照片原件能力。前端传素材来源、选区或图案、名称和草稿或标签 ID。后端成功保存可重开的图案后返回预览，保持用户原照片可用。选图取消或裁剪保存失败时，可重试或返回当前编辑状态。

**验收例子**　从一张围裙照片选取局部，制作「家的味道」并完成一条记录。给第二条记录选同一图章，再换图和更名「外婆的厨房」。重开后两条引用都显示新图案并可按新名称找到，源照片仍可完整打开。另在新草稿创建图章后放弃，其他记录的选择器里不出现该草稿私有标签。

### G07 感受刻度与地点体验

**需求依据**　[R098 自定义感受刻度](../B-整理关联与查找.md#r098-自定义感受刻度)、[R034 口味刻度](../C-地点与空间.md#r034-口味刻度)、[共用项目与变更规则](../B-整理关联与查找.md#共用项目与变更规则)。

**本次范围**　候选。自定义刻度项目及等级，选填本次值，通过项目和程度找回。用户在地点资料中维护「愿意再来」等整体印象，在单次记录中填写辣度等体验。已启用模板时可复用同一项目，无模板也能填写。

**接口与依赖**　复用地点身份、正式记录查询和草稿提交。前端提交项目身份、选中的等级和填写目标。后端区分地点共享资料与记录当次值，保存当时等级的含义，以明确选中的同一项目匹配旧记录。同名项目由用户决定选哪个。模板接口按相同项目身份读写一次。

**验收例子**　给面馆保存「愿意再来」，在两条用餐记录中以同一五级刻度填写 3/5、4/5。把定义改成十级，再新增一次 6/10。重开三条记录仍分别显示 3/5、4/5、6/10。按旧程度筛选能找到第一次。放弃草稿里对辣度的改动，小册里的地点印象和上次已完成的体验仍可见。

### G08 自定义状态

**需求依据**　[R099 自定义状态标记](../B-整理关联与查找.md#r099-自定义状态标记)。

**本次范围**　候选。建立自己命名、带图案的状态，在人物、物件、地点或单条记录上独立设置。可按当前状态查看，可主动留下带日期和说明的一次变化。更正误填值时允许只更新当前状态。

**接口与依赖**　依赖相关对象或正式记录的身份。前端提交目标类型、ID、选定状态，以及用户是否选择保留这次变化。后端保持目标之间的取值独立，用户选择留存时将状态和变化说明一起保存。失败后保留旧值，重试成功只产生本次确认的一条变化。

**验收例子**　把书改为「在读」，给一条读书记录另设「待整理」。将书改为「读完」并留日期、说明，再更正书的当前状态而不留存本次更正。重开时书和读书记录各有自己的状态，只有主动保留的那次变化出现。按「待整理」筛选仍能找到读书记录。

### G09 情境组合

**需求依据**　[R101 情境组合标签](../B-整理关联与查找.md#r101-情境组合标签)。

**本次范围**　候选。把多个已有标签保存为命名组合，一次套用，在记录上可逐项调整。从组合入口按全部选定条件找回。已交付 G07 时可在组合中加入指定刻度及程度，已交付图章时可为组合配图。

**接口与依赖**　基本组合仅依赖首版文字标签。前端传组合身份、所选标签及已启用的感受项。后端保存条件并按当前定义检查记录是否全部满足。套用的结果随记录草稿完成后生效，修改组合定义仅影响今后套用及其查询结果。若某个成员已失效，应指出需修正的条件，避免悄悄扩大查找范围。

**验收例子**　保存组合「雨天＋独处」。记录甲通过组合套用，记录乙逐项手动添加，记录丙只有「雨天」。按组合查询只出现甲乙。再将组合改为「雨天＋咖啡」，甲乙已有标签保持原状。给丙补「咖啡」并完成后从新版组合能找到丙。

### G10 地点待办

**需求依据**　[R035 下次想试](../C-地点与空间.md#r035-下次想试)、[R033 地点小册](../C-地点与空间.md#r033-地点页)。

**本次范围**　候选。从小册加入、查看及勾选“下次想试”的具体事项。给其中一项关联已有体验，或补一条新记录并关联。事项可以只勾选。建议允许一次事项关联多次到访的不同体验。这一取舍供评审。

**接口与依赖**　依赖地点小册、清单完成状态和正式记录身份。前端传地点 ID、事项 ID 与选定的体验 ID，或在新建草稿时记住发起事项。后端将勾选和关联分别保存，重复选中同一体验时保持一份引用。从事项补写的草稿保留在草稿入口，只有完成才出现正式体验。目标进入回收站时，事项仍保留。

**验收例子**　在一家店建立「豆花鱼」「靠窗座位」两项。只勾选「靠窗座位」，给「豆花鱼」关联一条点菜记录，再从该项新建体验并中途退出。重开小册，前者已勾选且没有体验，后者只显示已完成的点菜记录。续写并完成新体验后可从「豆花鱼」打开它，另一事项及另一家同名店均不增加此引用。

核对存储关系时可复用小份真实数据，页面验收重点观察所选对象、保存时机、返回位置和失败后的重试。具体表结构和方法名在各卡实现时选择。
