# 第二版专题 · 升级、备份与恢复

[返回第二版需求草案](../第二版需求草案.md)

用户需要办成两件事。一是在原手机更新 Folio 后，昨天拍的照片、写到一半的草稿和已整理的资料都能继续用。二是在原手机离线导出一份文件，在另一套受支持的安卓安装环境还原，并能继续编辑。覆盖安装与整包恢复分别验收。

产品依据为 R079 完整备份、R080 从备份恢复、R027/R028 删除恢复及候选的 R078 单条私密。首版数据基线取 `main@609908a` 的 Room v17。照片和录音另有 Folio 保存的原件。下文的入口名称、预检与确认流程、兼容策略是第二版建议。文件格式、保护方式和支持的版本组合待定。可分别核对[隐私与数据保护](../H-隐私与数据保护.md)、[已确认的保存关系](../../design/首版原型与关键数据设计.md#已确认的保存关系)、[首版验收进度](../../engineering/开发流程.md#当前开发进度)。

## 首版覆盖升级

1. 用户在设备上直接更新同一应用。升级后的第一次启动读取原资料并完成必要的迁移。正常进入「记录」时能够打开已有正式记录、媒体与草稿。升级日期不会变成旧记录的事件日期、首次记录时间或最后修改时间。
2. 没有加入组、章节和导览的旧记录继续出现在原有位置。用户可从旧记录第一次执行「加入记录组」。原有同名地点、人物别名及记录归属继续按其身份区分，可从小册或组合搜索找到原来的记录。
3. 旧数据迁移中断后再次启动，应能安全继续或给出可行动的失败说明。在迁移尚未成功时，保留已有资料，不把“打不开旧库”展示成“还没有记录”。首次运行时不要求用户先导出备份才能升级。
4. 覆盖安装验收使用同应用标识、可覆盖安装的版本号和同签名 APK，并保留旧版应用数据。没有可用的签名版本对时，在验收记录中分别写明已经验证的数据库迁移、调试包覆盖，以及仍待执行的签名包覆盖。旧版支持的系统范围见[设备兼容与交付](../版本规划与审核事项.md#设备兼容与交付已确认)。

### 制备一份可重复使用的首版样本

在空白的专用模拟器安装 `609908a` 构建的调试 APK，保留源 APK 和签名环境。首版的[Room v17 结构](../../../app/schemas/com.baconaa.folio.records.FolioDatabase/17.json)可供存储测试重建旧库。安装包覆盖还应走下面的真实入口，连同数据库一起保留 Folio 保存的照片和录音。

1. 从「写一句」输入「秋游」，用「添加内容」选一张虚构路线图并录制数秒测试声音，点「停止并保存」和「完成」。从正式详情加星、点「编辑」，追加「补记山路」，看到「草稿已保存」后返回。
2. 从「写一句」输入「明天带伞」，等草稿保存后返回。另写「旧车票」并点「完成」，在其编辑草稿追加「票面铅笔字」后返回。从正式详情删除「旧车票」，确认移入回收站。
3. 重启首版，核对「星标」能打开「秋游」并查看原图、播放录音。「搜索全部记录」找不到「补记山路」，「继续草稿」能分别续写「秋游」和「明天带伞」。回收站只有「旧车票」，只读详情提示另有未完成修改。保留此状态作为覆盖起点。
4. 记录源 APK 提交、模拟器 API 和上述结果，保存模拟器快照供各批复用。首个持久化变更交付时，从该起点使用 `adb -s <设备序列号> install -r <同签名目标APK>` 覆盖安装，保留应用数据。按 D01 核对后再恢复「旧车票」，确认能续写「票面铅笔字」。[现有迁移测试](../../../app/src/androidTest/java/com/baconaa/folio/records/TextDatabaseMigrationTest.kt)复用 v17 结构核对新迁移，安装包覆盖另记实际结果。

**调试包复验。** 在 `609908a` 的源码目录，把 `$probeScript` 设为当前仓库中[验收构建脚本](../../../qa/d01/d01-probe.gradle)的绝对路径，运行 `.\gradlew.bat --offline --build-cache -I $probeScript :app:assembleDebug :app:assembleDebugAndroidTest`。将这两个首版 APK 安装到空白专用模拟器。下列命令中的 `$serial` 是该设备的序列号，`$targetApk` 是同签名的新版应用，覆盖时保留首版测试 APK。[首版制样与页面用例](../../../qa/d01/androidTest/D01UpgradeProbe.kt)

```powershell
$runner = 'com.baconaa.folio.test/androidx.test.runner.AndroidJUnitRunner'
$probe = 'com.baconaa.folio.records.D01UpgradeProbe'
$expectedRoomVersion = 24
adb -s $serial shell am instrument -w -e class "$probe#seed" $runner
adb -s $serial install -r -t $targetApk
adb -s $serial shell am instrument -w -e expectedRoomVersion $expectedRoomVersion -e class "$probe#verifyAfterUpdate" $runner
```

验证失败重试时，从另一份已运行 `seed` 的首版样本开始。以下用例在 Room 写入新结构标识时制造故障。重开后从「记录」确认失败提示，解除故障并点击原页的「重试」，随后核对版本、原件和草稿。

```powershell
adb -s $serial shell am instrument -w -e class "$probe#blockUpgradeOnSeededFirstVersion" $runner
adb -s $serial install -r -t $targetApk
adb -s $serial shell am instrument -w -e class "$probe#failedUpgradeShowsRetry" $runner
adb -s $serial shell am force-stop com.baconaa.folio
adb -s $serial shell am instrument -w -e expectedRoomVersion $expectedRoomVersion -e class "$probe#retryAfterFailedUpgrade" $runner
```

## 一份完整备份包括什么

备份以一次已保存的数据状态为边界。用户在「完成」前写入草稿的内容可以备份。正在录制、尚未保存的片段不应显示成已备份。导出期间若继续编辑，以导出开始时取得的同一个一致状态为准，后续改动留给下次备份。读取这一状态用到的原件应保留到导出结束。

| 资料 | 恢复后的可见结果 |
|---|---|
| 有效正式记录、独立新草稿、已有记录的编辑草稿 | 正式入口展示上次完成的版本，草稿从「继续草稿」进入。保留可续写的内容、顺序、说明，以及原有版本已持久保存的编辑位置。 |
| 内容项与媒体原件 | 照片可看原图、录音可播放，文字和清单保留顺序、勾选状态。新版本已开放的视频、附件、导入音频和标注随对应内容一起导出。链接保留网址及用户自行保存的标题、备注和截图。 |
| 多处引用及回收站 | 同一张照片出现两次时保留两个位置与各自说明。仅被草稿、回收站或仍可撤销的已保存操作使用的原件也要保留。恢复后回收站仍只读，带草稿的记录在执行回收站恢复前继续隐藏。 |
| 时间、地点、人物、物件和标签 | 保留事件原话、精度、已存范围、时区信息与首次记录时间，以及对象身份、别名、区别备注、归属和星标置顶。零引用的正式对象可继续选用。草稿私有的新对象仍随原草稿。 |
| 记录组、专题导览、章节及直接关联 | 按本次已启用的范围保留成员、分段、排序、说明和引用。来源设备上的一条记录出现在两本册子中，恢复后仍指向同一条可编辑记录。已删除的目标按回收站既有规则处理。 |
| 用户保存的观察与回看选择 | 启用变化轨道后，保留对象、所选节点、来源素材和用户说明。已保存的回看排除项继续生效。如果选入未来胶囊，还需保留其选定内容、开启日期和提前查看状态。按日期或颜色得出的查询结果可从恢复后的资料重新计算。 |
| 照片识别与录音转写（启用 X02 或 X03 时） | 保留用户已经保存的文字、人工修订，以及它们与具体照片项或录音项的关联。恢复后使用改正过的站名或人名能找到对应原件。 |
| 地点待办与体验（启用 G10 时） | 保留所属地点、事项、勾选状态及各事项所关联的正式体验。同名的两家店仍有各自的事项。仅勾选的事项保持没有体验，已关联的事项能打开原记录。 |
| 设置、私密状态和其他已启用资料 | 用户保存的季节月份设置一并恢复，每条旧记录仍按原来已存的范围查询。启用阅读字号后保留应用内选择；选了「跟随系统」时按目标设备的系统字号显示。启用模板、标记或私密记录时，备份同步纳入对应定义、值和状态。 |

可重建的缩略图与查询索引可在目标设备重新生成。系统文件授权、旧设备的绝对路径和外部相册中的源文件不能作为找回媒体的前提。媒体从用户导入后已由 Folio 保存的原件恢复。用户选择“完整备份”时，如有应保存的原件缺失，应指出受影响的资料类型，保留可用的既有备份，避免把残缺文件报告为成功。

## 导出与找到文件

建议入口为「数据管理 → 创建完整备份」，与「从备份恢复」放在同一处。选择本地可写的位置，页面展示范围、文件名和将包含的应用资料。系统选择器取消后回到原页，当前资料保留。

| 操作阶段 | 用户可见结果 | 本机后端保证 |
|---|---|---|
| 准备与写入 | 每次导出创建新文件。同名时显示系统分配的新名称或提示另选名称。写入时显示阶段及能否取消，已知总量时可显示百分比。 | 写入前取得本次新建的目标。仅能打开已有文件进行覆盖时，返回重选位置。每次导出绑定同一批数据库内容与媒体，并避免多次点击交错写入。 |
| 成功 | 能找到刚保存的文件，看到实际文件名、可访问的位置和完成时间。 | 所需内容写完，文件已正确结束并能由预检识别后，再报告成功。之前的备份保留在原位置。 |
| 空间不够、目标不可写、用户取消、写入中断 | 告知失败阶段，用户可释放空间、改选位置或重试。本机原资料照常使用。 | 清理可控制的临时输出。若系统存储提供方留有残件，明确该文件未完成，后续恢复可识别并拒绝它。 |

## 备份版本与恢复预检

备份是可跨安装读取的数据文件。建议单独标识备份格式版本，记录创建时间、来源应用版本、所含数据类别以及核对原件所需的信息。Room 的版本用于应用库迁移，不能据其版本相同就判定一份备份能读。具体归档方式、校验算法和版本编号留给实现设计。

| 选中的文件 | 建议预检结果与动作 |
|---|---|
| 已支持格式，数据与原件齐全 | 显示备份摘要和目标资料摘要，允许进入确认。建议将正式记录、独立的新建草稿、已有记录的草稿和回收站分别计数，说明媒体按原件还是按内容项计数。 |
| 受支持的较早备份 | 按已公布的兼容范围导入到候选数据中，再检查旧的时间精度、媒体引用等。只为原包中没有的新增能力建立空状态。 |
| 更新或无法完整解释的格式 | 遇到无法保留的必需内容或关系时停止，说明所需版本或不支持的范围。用户可更新应用后重试，原设备数据可继续使用。 |
| 无法读取、截断、原件缺失或校验不符 | 提示重新选择可读文件、重新拷贝或重新备份。导入失败不会以跳过照片、草稿或关系的方式完成。 |
| 数据完整，但空间不足 | 在改动现有资料前说明无法容纳恢复所需的候选资料和临时空间。用户可先退出并释放空间，再重试。 |

预检要区分两种关系。组引用了本应在备份中出现的有效记录，而包里缺失该记录，属于备份不完整。某条回收站记录曾经属于一个后来已经删除的组，属于历史上合法的状态，恢复它时仍按“仅恢复有效关系”处理。预检应接受后者。[回收站恢复规则](../H-隐私与数据保护.md#删除恢复的共同规则)

## 从备份整体恢复

**建议首批采用单份备份整体恢复。** 同一台设备上已有的正式记录、草稿、回收站、媒体和设置都属于受影响范围。用户点选备份只触发读取与预检。在完整理解范围前可返回或改选文件。多份备份的合并、按条挑选和跨平台转换另行讨论。

1. **选择与核对。** 选中备份后显示来源版本、创建时间和可恢复的内容类别。目标为空时可提示“恢复到此设备”。有资料时并列显示备份与当前资料的摘要，明确完成后哪些本机资料会被整份替换。
2. **确认。** 建议在有资料的设备上提供“先备份当前资料”的入口，返回后继续核对。确认按钮直接写明“用此备份替换本机资料”。如果预检后用户又完成、删除或新增了记录，需要更新影响范围再继续。取消确认直接回到现有资料。
3. **准备与切换。** 在候选位置读取记录、设置、媒体及关系，准备期间允许取消。切换前再次核对目标资料与用户确认时相符。如果准备期间又保存了草稿，保留新草稿并返回影响摘要，待用户重新确认后再替换。短暂切换期间提示稍候，阻止会丢失的并发写入。用户重进页面或重复点确认应能看到同一任务的状态。
4. **结果与重启。** 仅在新资料可正常读取并已持久保存后显示成功，提供进入「记录」的入口。准备时失败或进程被终止，重新打开后仍能访问原资料。切换后进程被终止，重开后只能看到完整生效的一套资料，不能出现新记录配旧媒体、只有一半关系或重复恢复的记录。

## 私密范围与文件保护

单条私密属于独立候选。R078 启用后，用户主动做完整备份时要包含私密内容及其标记，并在导出前明确告知。其他主动对外提供资料的操作按原规则默认排除私密记录。恢复后，私密标记和默认回看范围应一同生效。若目标版本无法保持私密语义，建议拒绝该次整包恢复，避免意外公开。

Q08 仍需决定私密记录的访问方式与备份文件是否支持密码。界面说明应与文件实际采用的保护方式一致。选定无密码文件时，应清楚告知能取得文件的人可能读到其中资料。如决定提供密码保护，再确定启用方式、密码错误提示、找回能力及保护范围。应用内的私密标记和手机解锁状态不能直接说明备份受到了哪种文件保护。[待确认问题 Q08](../待确认问题.md)

### D01 首版覆盖升级与迁移

- **本批进度**　首版调试包直接覆盖至 M06 的 Room v24，以及迁移中断后的冷启动重试，已在 API 29 通过。正式签名包随 D04 验收。[v24 实测](../../engineering/开发流程.md#第二版-m06-创建模板并用模板起草) · [v23 实测](../../engineering/开发流程.md#第二版-m04-照片圈画的本机保存) · [v22 实测](../../engineering/开发流程.md#第二版-d01-首版覆盖到-room-v22)
- **需求依据**　已安装版本更新后仍能打开旧记录与媒体，草稿、正式内容和回收站保留各自的状态。[设备兼容与交付](../版本规划与审核事项.md#设备兼容与交付已确认) · [已确认的保存关系](../../design/首版原型与关键数据设计.md#已确认的保存关系)
- **本次范围**　以首版 Room v17、已保存的照片及录音为起点。每批涉及表结构、原件或关系的变更随相应功能交付兼容行为。旧记录没有新字段或关系时给出可继续使用的初始状态。旧数据库打不开时保留资料并显示错误，用户可重试。
- **接口与依赖**　前端在启动后读取本机后端的迁移与读取结果，成功才展示记录。失败时保留重试入口。后端负责旧记录身份、原始时间、草稿归属和文件引用在升级后的可读性。Room 迁移检查和模拟器安装包覆盖分别验证存储变更及启动入口。签名发布包的覆盖交给 D04。
- **验收例子**　用[首版样本](#制备一份可重复使用的首版样本)覆盖安装。搜索「秋游」能打开原图和播放声音，搜索「补记山路」仍无正式结果，两份活动草稿可续写。恢复「旧车票」后才可续写「票面铅笔字」。若迁移步骤中断，在测试安装里重新启动应得到完整可读的数据或能重试的错误。

### D02 离线导出一份完整备份

- **需求依据**　R079 要求用户主动选择本地位置，导出后可以找到文件。内容范围随已启用功能扩大。[完整备份](../H-隐私与数据保护.md#r079-完整备份)
- **本次范围**　从「数据管理 → 创建完整备份」走到可定位、可读取的本地文件。把同一时点已保存的数据、设置及原件写成一份备份，保留仅被草稿和回收站引用的媒体。涵盖选择器取消、目标不可写、空间不足和未完整写出的结果。
- **接口与依赖**　前端发起新文件选择，展示进度、能否取消、实际文件位置和最终结果。后端只向本次新建的目标写入，保护导出所用原件，返回状态及实际完成位置。在 D02、D03 共用样例中写清格式版本、记录与草稿的区别、媒体完整性以及新增类别的兼容说明。备份文件的密码保护按 Q08 另行评估。
- **验收例子**　用 D01 的虚构资料离线导出，在系统文件界面找到结果，经预检能识别正式记录、活动草稿、回收站及其媒体。导出开始后再保存一项文字，所得备份对应导出所取的那一刻，新增文字仍在源安装内。第二次选相同目录和原文件名，取得新名称后在写入中途取消或中断。若系统只提供覆盖，应用应在写入前提示重选。原文件仍通过完整性预检，和 D03 联验时仍能恢复「秋游」及草稿。若第二次留下残件，预检提示未完成。

### D03 预检与整份恢复

- **需求依据**　R080 要求恢复一份完整备份，恢复前说明影响范围，失败时保留目标设备原有资料。[从备份恢复](../H-隐私与数据保护.md#r080-从备份恢复) · [删除恢复的共同规则](../H-隐私与数据保护.md#删除恢复的共同规则)
- **本次范围**　识别兼容性、核对媒体与关系，向用户列出备份和目标资料摘要。由用户确认后整体恢复。准备阶段可取消。在切换边界处理进程中断、数据变化和重复确认。较新的不兼容格式或缺失必需原件时应说明原因。
- **接口与依赖**　前端先传入文件取得预检结果，返回或确认时带上用户刚核对的来源与目标状态。本机后端复核文件和目标数据是否变化，准备完整候选数据并安全切换。前端重新进入后从后端读取实际结果。开发可先使用与 D02 约定的合成样例。两卡联验使用 D02 实际导出的文件，从而覆盖编码与读取约定。
- **验收例子**　先在目标模拟器写下「目标草稿」，选有效包预检后取消，再选择一份缺原件的备份。退出预检后都能续写「目标草稿」。重新选有效包，核对期间若目标新增记录，应更新摘要并再次确认。完成整份替换后可读到源资料，界面事先告知会被替换的目标资料已移除。用可控制中断验证准备时重开仍见原资料，切换边界重开只见一套完整的数据和原件。再次进入不会重复恢复。

### D04 签名包跨版本与换机交付

- **需求依据**　每轮可用版本交付已签名 APK、实际变更和验证结果。旧版覆盖与换机恢复检验两条不同的用户路径。[设备兼容与交付](../版本规划与审核事项.md#设备兼容与交付已确认) · [完整备份与恢复](../H-隐私与数据保护.md#h3-备份恢复与提醒)
- **本次范围**　用同一份已知源数据、发布候选包及独立的干净安卓安装完成串联。记录实际源包与目标包版本、签名覆盖适用范围、备份格式、环境与观察。发布验证可用符合支持范围的模拟器。
- **接口与依赖**　D01 提供迁移能力，D02 与 D03 提供用户可操作的导出、预检和恢复入口。前端在恢复生效后刷新草稿、详情、回收站和设置。本机后端在新安装中提供已持久保存的关系、排序与原件。覆盖步骤需同应用标识、版本号可升级的同签名源包和目标包。如果源包缺失，先完成可独立执行的干净安装、备份往返和迁移验证，将这组签名覆盖结果标为待验。
- **验收例子**　保留 D01 样本，升级后导出并在干净安装恢复，断网打开「秋游」原图并播放录音。若此版交付 G01，导出前把甲组排为「秋游、维修」，乙组排为「购票、秋游」。恢复后逐组核对两份顺序，从甲组完成正文修改，乙组打开同一条更新。再用两个同名但街道不同的地点及一条跨年冬季记录，核对更改季节设置后，旧事件范围和地点身份在换机后仍准确。若此版交付变化轨道，再核对该照片上的观察说明与来源。可复用 D01、D03 已覆盖的故障结果。

### D05 单条私密与回看保护

- **需求依据**　候选 R078 要求用户可主动查看私密记录，默认排除主动回看和对外提供资料。完整备份应保留私密内容和标记。访问验证、主动选取和文件保护遵循 Q08 的待定范围。[单条私密记录](../H-隐私与数据保护.md#r078-单条私密记录) · [待确认问题](../待确认问题.md#后续阶段确认的问题)
- **本次范围**　若选入本卡，先按 Q08 明确主动访问与主动选取的方式，提供设置、查看和取消私密的操作。在各回看、对外提供资料或完整备份入口上线时接入对应的保护规则。备份导出前说明会包含私密资料，并说明文件实际采用的保护方式。
- **接口与依赖**　前端区分主动访问、主动对外选取、普通回看及完整备份入口。本机后端统一保存标记并按已选场景提供可见结果。与本版已启用的同日、季节或随机回看入口联验。启用 D02、D03 时，备份读写双方都要识别该标记。建议对不能保留私密语义的文件或目标版本停止恢复，并给出可行动的原因。
- **验收例子**　准备两条同月日的正式记录，仅将含照片的一条标为私密。重启后按约定的主动访问方式查看标记和原图，取消私密后重开，确认标记已清除，另一条记录始终是普通记录。涉及以下已启用入口时，在同一份样本上重新标为私密并联验。
  - 同日或季节回看默认只返回普通记录。已启用随机回看时，核对其候选集排除私密记录。已启用对外选取时，核对默认选取结果排除该记录。
  - 已启用 D02、D03 时，离线备份前能看到包含私密资料的提示。恢复到干净安装后可主动打开私密原图，私密标记仍在，已启用的回看入口第一次打开即遵守该标记。
